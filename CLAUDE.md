# LeetCode Solutions

C# / .NET 10 repository of LeetCode problem solutions with xUnit tests.

## Project Structure

```
Solutions/<ProblemName>/Solution.cs   # one solution class per problem
Tests/<ProblemName>Tests.cs           # corresponding test file
create_problem.sh                     # scaffolding script
```

## Commands

```bash
dotnet build                          # build the solution
dotnet test                           # run all tests
dotnet test --filter "ClassName"      # run tests for a specific problem
```

## Adding a New Problem

Use the scaffolding script — it creates the solution file, test file, and git branch in one step:

```bash
./create_problem.sh "two-sum"         # kebab-case input
./create_problem.sh "TwoSum"          # PascalCase input also accepted
```

This creates:
- `Solutions/TwoSum/Solution.cs` with a stub `Solution` class
- `Tests/TwoSumTests.cs` with a placeholder test
- A new git branch `two-sum`

Each problem lives on its own git branch. Open a PR to `master` when the solution and tests are complete — CI runs `dotnet test` on every PR.

## Solution File Conventions

**File:** `Solutions/<ProblemName>/Solution.cs`

```csharp
namespace Solutions.TwoSum;

public class Solution
{
    public int[] TwoSum(int[] nums, int target)
    {
        // implementation
    }
}
```

- Namespace: `Solutions.<ProblemName>` in PascalCase (matches the folder name exactly)
- Class is always `public class Solution`
- Method name and signature must match the LeetCode problem exactly (PascalCase)
- Private helper methods are `private static`
- Nullable enabled — avoid unnecessary null checks on internal code; validate only at boundaries
- Multiple approaches for the same problem can coexist as separate public methods on the same class

## Test File Conventions

**File:** `Tests/<ProblemName>Tests.cs`

```csharp
using Xunit;
using Solutions.TwoSum;

namespace Tests;

public class TwoSumTests
{
    [Theory]
    [InlineData(new[] { 2, 7, 11, 15 }, 9, new[] { 0, 1 })]
    [InlineData(new[] { 3, 2, 4 }, 6, new[] { 1, 2 })]
    public void TestSolution(int[] nums, int target, int[] expected)
    {
        var solution = new Solution();
        Assert.Equal(expected, solution.TwoSum(nums, target));
    }
}
```

- Test class: `<ProblemName>Tests`
- Test method: always `TestSolution`
- Use `[Theory]` + `[InlineData]` for parameterized cases (preferred over `[Fact]`)
- Cover edge cases: empty arrays/strings, single elements, boundary values
- For in-place mutations (e.g. `Rotate`, `MoveZeroes`), call the method then assert on the modified input
- Use `Assert.Equal` as the primary assertion
- When multiple solution approaches exist on the class, call all of them in the same test

## Namespace Note

Older solution files (e.g. `BestTimeToBuyAndSellStock`) used all-lowercase namespaces (`Solutions.Besttimetobuyandsellstock`). New files generated by `create_problem.sh` use PascalCase. Match whatever namespace is already in the file being edited; use PascalCase for any new files.
